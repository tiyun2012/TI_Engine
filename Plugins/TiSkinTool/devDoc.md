TiSkinTool: UE 5.8 Architecture & Implementation Guide1. Core Architecture Strategy: "The Hijack"Instead of building a custom Interactive Tool from scratch and fighting Epic's internal setup (Target Managers, Material Providers, Geometry Selection), this plugin uses a hijack strategy.UI Injection: We inject a custom Ti Skin Debug button into the Skeletal Mesh Editor toolbar.Tool Replacement: When clicked, the button accesses the editor's UInteractiveToolManager and overwrites Epic's native "SkinWeightsPaintTool" string identifier with our custom UTiSkinWeightToolBuilder.Native Execution: When the user subsequently clicks the standard "Skin Weights" tab in the editor, Epic's mode handles all complex environment setup, but safely spawns our derived tool instead of the base tool.2. C. The Core Tool (TiSkinWeightTool.cpp)The active state machine that reads data and intercepts viewport interactions. Inherits directly from USkinWeightsPaintTool.1. The Shutdown() VTable Bypass:Crucial Rule: Do not declare or override virtual void Shutdown() in your header or cpp file.Reason: Epic forgot to export UDynamicMeshBrushTool::Shutdown from their DLL in UE 5.8. Statically calling Super::Shutdown() causes a fatal linker error. By omitting it, the compiler defers to the runtime vtable, successfully bypassing the unexported symbol.2. 4. Known UE 5.8 Quirks to RememberLive Coding Limitations: Live Coding (Ctrl+Alt+F11) cannot patch editor-level tool registrations safely. When changing the TiSkinToolModule registration logic, you must close the editor and perform a Clean Rebuild in Visual Studio to flush the old DLL from memory.Delegate Cleanup: Because we bind delegates using AddUObject(this, ...), Unreal's garbage collection automatically unbinds them when our tool instance is destroyed. Manual RemoveAll() cleanup is not strictly necessary, saving us from needing the Shutdown override.Target Component vs GetMesh: Never try to cast GetMainMeshSelector()->GetTargetComponent() directly to read weights. The tool operates on a temporary FDynamicMesh3 wrapper, not the raw USkeletalMesh asset
